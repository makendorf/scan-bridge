# Visual Scripting System — Phase 1 (MVP)

## Overview
Замена линейного списка пост-скан действий на графовые сценарии в стиле Unity Visual Scripting / Unreal Blueprints. MVP: модели, движок для линейных графов, веб-редактор на Drawflow, API CRUD, интеграция с PostScanManager.

## 4. Execution Engine

### `src/Services/VisualScripting/ScenarioExecutor.cs`
Runtime engine для выполнения графовых сценариев:

**Ключевые решения:**
- Граф топологически сортируется при загрузке (Kahn's algorithm)
- Для линейных графов (Start → Action → ... → End) — простой последовательный обход
- Condition узлы: evaluation через simple expression engine (regex, contains, equals)
- Каждый узел оборачивается в try/catch
- `ScenarioContext` передаётся между узлами

```csharp
public class ScenarioContext {
    public ScanResult Scan { get; set; }
    public Dictionary<string, object> Variables { get; set; } = new();
    public Dictionary<string, object> NodeOutputs { get; set; } = new();
    public CancellationToken CancellationToken { get; set; }
}

public class ScenarioExecutor {
    // Compile: validates graph, builds adjacency, checks for cycles
    public CompiledScenario Compile(ScenarioConfig scenario, IPostScanActionFactory factory);
    
    // Execute: runs compiled scenario with context
    public async Task ExecuteAsync(CompiledScenario compiled, ScenarioContext context, CancellationToken ct);
}
```

**CompiledScenario** — pre-compiled graph structure:
```csharp
public class CompiledScenario {
    public ScenarioConfig Config { get; }
    public CompiledNode StartNode { get; }
    public Dictionary<string, CompiledNode> Nodes { get; }
    // Topologically sorted execution order for linear paths
}
```

**CompiledNode** — pre-resolved node with action instance:
```csharp
public class CompiledNode {
    public ScenarioNodeConfig Config { get; }
    public IPostScanAction? Action { get; }  // null for Start/End/Condition
    public List<CompiledNode> NextNodes { get; }  // from connections
}
```

### `src/Services/VisualScripting/ConditionEvaluator.cs`
Простой evaluator для Condition узлов:
- Regex match
- Contains / NotContains
- Equals / NotEquals
- GreaterThan / LessThan
- IsValid check

## 6. Integration with PostScanManager

### Changes to `src/Services/PostScanManager.cs`
Добавить загрузку и выполнение сценариев параллельно с группами:

```csharp
// Новые поля:
private volatile IReadOnlyList<CompiledScenario> _scenarios = Array.Empty<CompiledScenario>();

// Новый метод:
public virtual void ConfigureScenarios(List<ScenarioConfig> scenarioConfigs, IPostScanActionFactory factory);

// Изменение ExecuteAllAsync — добавить выполнение сценариев:
public virtual async Task ExecuteAllAsync(ScanResult scan, CancellationToken ct) {
    // ... существующий код для групп ...
    
    // Новое: выполнение сценариев
    var matchingScenarios = _scenarios.Where(s => MatchesScanner(s.Config, scan.ScannerName)).ToList();
    var scenarioTasks = matchingScenarios.Select(s => ExecuteScenarioAsync(s, scan, ct));
    await Task.WhenAll(groupTasks.Concat(scenarioTasks));
}
```

## 13. Key Design Decisions

1. **Drawflow** chosen for frontend — lightweight, vanilla JS, fits project style
2. **Backward compatibility** — existing PostScanActionGroups continue working alongside scenarios
3. **ScenarioExecutor** compiles graph at load time (not per-scan) for performance
4. **Condition evaluator** is intentionally simple (no full expression engine) — regex + string ops + comparisons
5. **Node positions stored as doubles** — Drawflow uses pixel coordinates, needs floating point
6. **Scanner binding** on scenario level (same as groups) — list of scanner names, empty = all
7. **SortOrder** on Scenarios for UI ordering, same pattern as groups
8. **No real-time graph validation** in backend — only on save via `/validate` endpoint
